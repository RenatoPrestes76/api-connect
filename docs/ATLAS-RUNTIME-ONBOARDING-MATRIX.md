## Supporting evidence (file:line)

- **Ed25519 registration lookup**: `runtime-registration-store.ts:150` — `portalIdentityStore.findOrganizationByCode(input.organizationCode)`. Not Prisma.
- **portal-identity Organization**: `portal-identity-store.ts:28` — `private organizations: OrganizationRecord[] = []`, `randomUUID()`-keyed, zero `prisma.` calls in the whole file (confirmed by full-file grep).
- **Prisma `Organization`/`Tenant` graph**: `packages/database/prisma/schema.prisma` — `Tenant` (454) `1—*` `Organization` (474, nullable `tenantId`) `1—*` `Workspace` (561) `1—*` `Environment` (584) `1—*` `Agent` (610, both `organizationId` and `environmentId` FKs).
- **control-plane's own in-memory `Runtime`**: `control-plane-store.ts` imports `Runtime`/`RuntimeAccessToken` from its own `types.ts` — a _third_, disconnected "Runtime" concept from both Ed25519's `RuntimeRegistrationRecord` and Prisma's `Agent`. Seeded with fake data (`mkRuntime(orgAcme, ...)`), never written to by any real registration flow. Powers `/admin/control-plane/runtimes` (a generic "fleet" admin page), not `/atlas-runtimes`.
- **Agent legacy's real FK**: `agent.service.ts:39-43` — `prisma.agent.findFirst({ include: { environment: {...}, organization: {...} } })` — proves a real Prisma relation exists, unlike the other two flows' Organization concepts.
- **Agent legacy's broken client**: `apps/agent/src/bootstrap/bootstrapper.ts`'s `_registerWithCloud()` body omits `organizationId`/`environmentId`, which `apps/api/src/routes/v1/agents.ts`'s `registerAgent()` requires (400 if missing) — traced directly, not assumed.
- **AtlasAgent's unvalidated companyId**: `packages/database/prisma/schema.prisma:50` — `companyId String` (no `@relation`). No `model Company` exists anywhere in the schema (confirmed by grepping all `^model` lines).
- **"Atlas Runtimes" UI is the Ed25519 flow's admin surface**: `apps/admin/src/app/api/admin/atlas-runtimes/[...path]/route.ts`'s own comment: _"Proxies to apps/api's /admin/runtime-registration/_ — the real on-premise ERP-connector Runtime, distinct from the fleet '/admin/fleet/_' Runtime concept."_
- **apps/runtime-installer has no consumer in this repo**: no `package.json` outside `apps/runtime-installer/` references `@seltriva/runtime-installer` (grepped repo-wide).

## What this proves

Three completely disjoint ID spaces claim the word "Organization": Prisma
`Organization.id` (cuid, real FK to Tenant, admin-visible via Control
Plane's Tenants/Organizations pages), portal-identity's `OrganizationRecord.id`
(UUID, in-memory, non-durable), and `AtlasAgent.companyId` (a free string
with no referential integrity at all). Only one of the three enrollment
flows — Agent legacy, via Prisma `Agent` — has genuine FK-enforced
Organization/Environment integrity, and its own client is currently
non-functional. Only one flow — Ed25519 — has real cryptographic security,
replay protection, and ERP discovery (GENESIS/ATHENA) capability, and it
already has both a real client (`apps/agent/src/atlas-runtime-client/`) and
a dedicated admin UI page ("Atlas Runtimes"). See the ADR for the decision
this evidence supports.
