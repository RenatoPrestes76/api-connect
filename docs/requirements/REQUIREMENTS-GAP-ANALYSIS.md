## Priorização recomendada (não é uma nova sprint automática — apenas ordenação de backlog)

1. **GAP-02 / GAP-03** — decisão de modelo de autorização para rotas staff-gated e para o módulo `/admin/*` legado. Requer decisão de produto (existe delegação por tenant para roles admin, ou todo admin é sempre platform-wide?) antes de qualquer código.
2. **GAP-09** — corrigir a assinatura enganosa de `restore()`/`runRecoveryTest()` (mínimo: documentação inline + possivelmente remover o parâmetro `tenantId` da API pública se o escopo real nunca será implementado).
3. **GAP-04** — persistência do restante de `admin-identity` (sessões/login-attempts/audit-log), usando a mesma técnica de exclusão-em-testes já validada para `AtlasAdminUser`.
4. **GAP-05 / GAP-06** — decisão coordenada do usuário: aceitar o risco residual (documentado, baixo risco real) ou planejar a migração major de vitest como um projeto à parte, testado isoladamente antes de mesclar.
5. Demais itens (GAP-07, GAP-08, GAP-10, GAP-11) são informativos ou requerem decisão de produto sem urgência de segurança.
